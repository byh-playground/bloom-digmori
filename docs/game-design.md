# 디그모리 게임 기획 (재정리 초안)

기준 커밋: main 5f8d1b8 · 제품 0.28.14 · GameKit 고정 `418e17c`(v0.14.3, 최신 v0.37.0 계열은 1단계에서 교체)

이 문서는 규칙 AI-001·002·004·005·008·012의 순서(의도 → 조사 → 동작 확정 → 구현)를 따른 기획 원본이다. 수치와 단계 이름은 **초안(가설)** 이며, 수직 슬라이스를 직접 플레이해 재미를 확인한 뒤 확정한다. 확정되기 전의 내용을 확정 사양으로 취급하지 않는다(AI-002).

## 1. 근거 구분 (AI-004)

| 구분 | 내용 |
|---|---|
| 사용자 요구 (확정) | 복셀 월드 + 빌보드 캐릭터 렌더 유지. 수동으로 시작해 점점 자동화. 획득한 유닛으로 전투. 렌더 교체. GameKit 최신화. **멀티(락스텝 결정론)는 처음부터 전제. 시뮬레이션은 구조적으로 부동소수를 쓰지 않는다**. 기존 아트·렌더는 모킹용이라 버리고 전부 새로 만든다. **마크식 성장(자원 → 장비 → 보스 → 다음 단계), 진행 축은 한 월드 안의 바이옴(포탈 없음), 단계는 장비 페널티로 구분, 이전 바이옴 자원이 이후에도 필요**. **버드모리처럼 키우는 소수 정예(정원 12, 편성 4), 알 → 부화 → 성장 → 같은 등급 합성, 자원은 영역에 들어가면 자동 채집, 유닛 3종, 보스는 유닛 몸 ×3 + 모자 하나**. 인디게임(스팀) 수준을 목표로 하되 적은 리소스로 재미를 낸다 |
| 조사로 확인 | ① Factorio 개발진은 수동 채굴 → 자동 채굴 → 자동 물류 → 자동 생산 순서를 진행의 핵심 축으로 둔다. 각 단계가 *직전까지 손으로 하던 일*을 대체하므로 업그레이드가 값져 보인다 ([FFF-327](https://factorio.com/blog/post/fff-327)). ② Palworld는 개체마다 작업 적성이 있고 적성 등급이 높을수록 작업이 효율적이다. 월드가 로드된 동안만 일하고 먹이·휴식이 필요하다 ([Mobalytics](https://mobalytics.gg/gamebase/guides/palworld-base-pal-guide), [HostedGG](https://hostedgg.com/blog/palworld-base-building-guide)). 이 게임은 적성·분업 체인이 Palworld와 너무 비슷해 쓰지 않는다. ③ Rapier JS 빌드는 같은 빌드·같은 timestep에서 교차 플랫폼 결정론을 주장하지만 내부는 부동소수이고, `Math.sin/cos` 같은 초월함수는 플랫폼마다 다를 수 있다([Rapier 결정론](https://rapier.rs/docs/user_guides/javascript/determinism)). 이 게임은 결정론을 라이브러리의 보증에 맡기지 않고 **시뮬레이션 상태를 정수·고정소수로 둔다**(§5) |
| 직접 만든 목업으로 확인 | 한 페이지에 탭으로 묶은 클릭 목업(필드 · 농장 · 제작 · 보스전)에서 아래를 시험했고 사용자가 "괜찮다"고 확인했다: 필드 자동 채집·야생 병아리 사냥·알 드롭, 농장 부화·성장·합성·편성, 장비 제작과 페널티, 보스 패턴. 목업은 일회용이라 저장소에 남기지 않는다. 그 수치는 모두 가설이다 |
| 이번 초안 | 아래 2~7절 전체 |
| 미확인 | 서로 다른 브라우저·OS 조합의 실제 비트 일치(현재 검증은 동일 PC 2인 RTC까지). 목업은 부동소수 시연이라 정수 시뮬레이션의 체감은 아직 확인하지 못했다. AI 아트의 원본 해상도 PNG는 아직 받지 못했고 화면 캡처로만 시험했다 |

## 2. 한 문장

> 필드에서 자원과 알을 얻어 농장에서 소수 정예 유닛을 키우고, 광석으로 장비를 만들어 보스를 쓰러뜨리며 다음 바이옴으로 간다. 이전 바이옴의 자원도 계속 필요하므로 손으로 하던 수급을 유닛에게 점점 넘겨 더 먼 곳으로 간다.

## 3. 성장 구조와 유닛

### 3.0 확정한 방향 (사용자 결정)

| 항목 | 결정 | 이유 |
|---|---|---|
| 성장 방식 | 마크식: 자원 수집 → 장비 제작 → 보스 처치 → 다음 단계. 한 세계에서 오래 성장 | 짧은 런이 아니라 장기 성장을 원함 |
| 진행 축 | 수평 **바이옴** | 깊이 기반은 수평은 무한한데 수직 단계는 수십 m라 스케일이 어긋남 |
| 월드 구조 | **한 월드 안에 바이옴이 놓인다**(마크식). 포탈은 쓰지 않는다 | 포탈은 탭 전환일 뿐 이동 비용이 없었다. 한 월드면 거리가 곧 비용이다 |
| 단계 구분 | 바이옴 입장은 자유. **장비를 못 갖추면 큰 페널티**를 받는다(막지 않는다) | 문이 아니라 준비도로 단계가 나뉜다 |
| 바이옴 간 관계 | 이전 바이옴의 자원이 이후에도 필요하도록 설계 | 한 번 지나가면 끝나는 직선 진행을 피하고 지역이 낭비되지 않게 함 |
| 전투 | 내가 조작 + 유닛 지원 | 기존 결정 유지 |
| 육성 느낌 | 버드모리처럼 키우는 소수 정예, 농장 운영 | 많은 개체를 굴리는 방식보다 한 마리의 가치가 큰 쪽 |
| 정원·편성 | 보유 정원 12, 전투 편성 4 | 소수 정예 |
| 획득 | 알은 그 바이옴의 종이 드롭 → 농장에서 부화 → 새끼 → 성체. **번식은 없다** | 짧은 사이클과 드롭 보상 |
| 성장 | 새끼가 성체가 되려면 먹이가 든다(목업 초안: 3). 성숙 단계는 없다 | 단순함 |
| 합성 | 같은 종 · 같은 등급 2마리를 합쳐 +1등급. **유저가 농장에서 직접** 한다 | 농장에 들르는 이유를 만든다 |
| 역할 | 저등급은 노동, 고등급은 전투. 노동 효율은 등급당 ×1.5, 전투력은 등급당 ×3 (원칙. 목업은 더 완만한 값을 썼다) | 합성이 용도를 바꾸는 구조 |
| 채집 | 자원은 영역에 들어가면 **자동**으로 채집된다 | "버튼 누르는 게 귀찮다" |
| 자동화 | 농장 시설로 확장한다(시설 종류·건설 방식은 §8) | 수동 → 자동의 승급 수단 |
| 보스 | 유닛 등급 1 몸 ×3 + **정적인 모자 하나**만 다르다(애니메이션에 들어가지 않는 디테일) | 유닛과 구분되면서 아트 비용이 거의 안 늘어난다 |

**폐기한 방향:** 깊이 축, 거리 링 축, 포탈로 연결한 별도 바이옴, 적성·작업장·분업 체인(Palworld와 너무 비슷함), 번식과 성숙 단계, 보스가 동료로 합류하는 안(보스는 재료와 왕관을 떨군다). 이유는 기록으로만 남긴다.

**멀티 영향:** 공간이 하나라서 "서로 다른 바이옴을 같이 갱신"하는 문제가 없다. 플레이어 주변 활성 영역 방식을 그대로 쓴다.

### 3.1 유닛 흐름

```text
[필드] 야생 유닛 사냥 ─▶ 알 드롭 ─▶ [농장] 부화 ─▶ 새끼 ─(먹이)─▶ 성체 등급 1
                                                          │
                        같은 종·같은 등급 2마리 ──합성──▶ 등급 +1 (최대 4)
                                                          │
                  상위 4마리 = 전투 편성 / 나머지 = 노동(먹이·광석 자동 수급)
```

- 정원 12는 알·새끼·성체를 모두 합친 수다. 가득 차면 알을 얻어도 담지 못하므로 합성이 자리를 비우는 수단이다.
- 목업에서 성체 이후 등급은 크기와 별 표시로만 구분했다. 등급별 전용 그림은 아직 쓰지 않는다.
- 등급이 오를수록 유닛 몸의 광석 장식이 늘어난다(§3.2 바위 병아리: 총 2/3/5/7개).

### 3.2 종 (유닛 3종)

컨셉 기준: 두 요소를 조합한 이름이고(버섯 + 달팽이처럼), 매력적이고 독창적이며 그리기 쉬워야 한다. 광맥 지네·포자 군주·두더지·아르마딜로는 매력이 없어 폐기했다.

| 종 | 바이옴 | 상태 |
|---|---|---|
| **뿌리** | 초원 | 확정. 4방향·성장 줄·동작 시트 제작 완료 |
| **바위 병아리** | 동굴 | 확정. 캐릭터 시트와 부품 시트 제작 완료 |
| **버섯 달팽이** | 균류 숲 | 확정(v3 디자인). 4방향·성장 줄·동작 시트 제작 완료 |

**바위 병아리 (확정):** 바위 알 + 병아리. 둥근 노란 병아리가 위쪽 바위 껍질(모자, 아래 가장자리가 톱니)과 아래쪽 바위 껍질(그릇, 위 가장자리가 톱니) 사이에 앉아 있다. 껍질에 광석 덩어리가 울퉁불퉁 붙어 있고 광석은 등급 1~4에서 철, 청수정, 구리, 금으로 늘어난다(총 2/3/5/7개). 알은 같은 바위 알. 보스는 **광맥 병아리 대왕**(등급 1 몸 ×3 + 금광석 왕관).

**뿌리 (확정):** 통통한 새싹 무. 크림색 둥근 몸에 짧은 뿌리 발과 팔, 머리 위에 잎사귀 세 장이 모자처럼 난다. 등급이 오르면 잎이 늘고 꽃봉오리, 노란 꽃 1~2송이가 핀다. 알은 새싹이 튼 흙덩이 알. 기본 공격은 잎사귀 박치기, 스킬은 **뿌리 박기**(웅크림 → 점프 → 내려찍으며 땅에서 뿌리와 흙이 터짐 → 어질어질 회복). 보스는 **뿌리 대왕**(등급 1 몸 ×3 + 금빛 꽃 왕관).

**버섯 달팽이 (확정):** 크림색 달팽이 몸에 빨간 점박이 버섯 갓이 나선 껍질이다. **눈은 얼굴에 작은 점 눈으로 두고 더듬이는 눈 없는 평범한 더듬이로 둔다**(줄기 끝 눈은 징그럽고 큰 눈은 귀엽지 않다는 판단, 작은 미소와 분홍 볼터치). 등급이 오르면 껍질이 커지고 작은 버섯이 2, 3, 5, 7개로 늘어난다. 알은 버섯 점이 박힌 알. 기본 공격은 껍질 박치기, 스킬은 **포자 터뜨리기**(갓이 부풀다가 터지며 노란 포자 구름과 충격파). 보스는 **버섯 대왕 달팽이**(등급 1 몸 ×3 + 금빛 버섯 왕관).

세 종 모두 같은 동작 틀(준비 · 젖힘 · 내지름 · 반동 + 웅크림 · 돌진 · 충돌 · 회복)을 쓴다.

| 동작(바위 병아리) | 내용 |
|---|---|
| 기본 공격 | 쪼기: 준비 → 머리 젖힘 → 부리 내지름 → 반동 |
| 스킬 | 바위 박치기: 웅크림 → 돌진 → 충돌(별·파편·충격파) → 어질어질 회복. 쿨다운 6초 |
| 특수 | 껍질 쏙(껍질 안으로 숨기) |

### 3.3 장비 페널티 (확정한 원칙 + 목업 초안 수치)

원칙: 장비 없이도 들어갈 수 있지만 얻는 것이 크게 줄거나 잃는 것이 크게 는다. 그래서 장비를 맞추는 것이 진행의 단계가 된다.

목업의 초안(동굴 기준, 전부 가설):

| 슬롯 | 맨손(페널티) | 철(권장) | 청수정 |
|---|---|---|---|
| 곡괭이 | 채집 ×0.35 | 보통 | ×1.5 |
| 무기 | 공격 ×0.4 | 보통 | ×1.6 |
| 방어구 | 추위로 체력이 닳고 받는 피해 ×2 | 보통 | 받는 피해 ×0.6 |

| 티어 | 재료(초안) |
|---|---|
| 철 | 곡괭이 철 8 / 무기 철 6·구리 3 / 방어구 철 10·구리 4 |
| 청수정 | 곡괭이 철 6·청수정 8 / 무기 청수정 8·구리 5 / 방어구 청수정 10·**보스 왕관 1** |

청수정 방어구에 보스 드롭(왕관)이 들어가므로 다음 단계 장비를 만들려면 보스를 잡아야 한다. 바이옴별 권장 장비는 초원 맨손, 동굴 철, 균류 숲 청수정이다(목업에서 균류 숲은 같은 방식으로 포자 독 페널티를 시험했고, 초원은 페널티가 없다). 목업에서는 모든 슬롯이 권장 미만일 때 화면 가장자리가 푸르게 변하고 "장비 페널티" 문구가 뜬다. 이 수치는 슬라이스 플레이 후 조정한다(AI-008).

### 3.4 전투

플레이어가 직접 움직이고 공격하며 편성된 유닛 4마리가 지원한다. 유닛은 알아서 보스를 쪼고 6초마다 스킬을 쓴다. 맞으면 밀려나 기절하고 쓰러져도 일정 시간 뒤 일어난다. 보스는 아래 패턴을 번갈아 쓴다(목업 초안).

| 패턴 | 내용 |
|---|---|
| 걷기 | 가장 가까운 대상을 쫓아 쿵쿵 걷는다 |
| 부리 공격 | 뒤로 젖힌 뒤 부리를 내지른다 |
| 점프 내려찍기 | 웅크리는 동안 바닥에 붉은 원이 뜨고, 뛰어올라 그 자리에 내려찍는다 |
| 돌진 | 바닥에 붉은 길이 뜬 뒤 직선으로 달린다. 벽에 부딪히면 **기절**해서 받는 피해가 커진다 |
| 분노 | 체력 절반에서 포효하고 돌이 떨어지며 이후 더 빠르게 움직인다 |

체력 막대·떨어지는 광석·붉은 예고 표시가 읽혀야 하므로 보스는 "살아 있다"는 느낌을 위해 유닛 이상의 동작 수를 가져야 한다(목업에서 한 장 그림에 미세 흔들림만 넣었을 때 사용자가 살아있지 않다고 지적했다).

### 3.5 제안 (미확정)

아래는 확정 사항에서 파생한 **제안**이다. 사용자 확인 전에는 사양으로 취급하지 않는다(AI-002).

**① 순환 자원 요구가 자동화의 동기가 된다.** 바이옴 N의 장비 레시피에 이전 바이옴의 자원이 하나씩 들어간다(예: 청수정 방어구에 철 곡괭이 재료가 쓰인다). 처음에는 걸어서 오가며 직접 모으지만 바이옴이 깊어질수록 이동 비용이 커진다. 그때 이전 바이옴의 수급을 노동 유닛과 농장 시설에 넘기는 것이 "수동 → 자동화"다.

**② 월드는 유한한 반경.** 거점을 중심으로 걸어서 몇 분 안에 닿는 반경에 바이옴 조각을 시드로 배치한다. 무한 월드에 거리로 단계를 늘어놓으면 한 방향으로만 가서 지역이 낭비되기 때문이다. 무한 확장은 후속으로 미룬다.

```text
        [동굴 · 바위 병아리]
            │
[초원 · 뿌리] ─ [거점·농장] ─ [균류 숲 · 버섯 달팽이]   ← 바이옴 조각은 시드로 배치
```

**③ 에셋 규모 추정 (가설).** 바이옴당 타일 6~8종, 유닛 1종(4방향 × 동작 + 표정 + 껍질·장식), 야생 개체, 보스 모자 1개, 장비 아이콘 몇 개. 3종 기준 합계는 아트 단계에서 실측한다.

### 정상·반례 사례 (AI-005)

- 정상: 동굴 필드에서 유닛이 철·구리를 자동으로 캔다 → 야생 병아리를 잡아 알을 얻는다 → 농장에서 부화·성장시키고 같은 등급 둘을 합성한다 → 철 장비를 만든다 → 보스를 잡고 왕관을 얻는다 → 왕관으로 청수정 방어구를 만들어 균류 숲으로 간다.
- 반례 1: 장비 없이 동굴에 들어가면 입장은 되지만 채집이 느리고 공격이 약하고 추위로 체력이 닳는다. 무엇이 부족한지 화면에 표시한다.
- 반례 2: 정원 12가 가득 차면 알을 얻어도 담기지 않는다. 합성으로 자리를 비워야 한다는 것을 알려 준다.
- 반례 3: 먹이가 부족하면 새끼가 성체로 자라지 못하고 "먹이 부족"이 표시된다. 노동 유닛이 먹이를 모은다.
- 반례 4: 멀티에서 한 명은 동굴, 다른 한 명은 초원에 있다. 한 월드이므로 활성 영역 방식으로 둘 다 같은 틱에 갱신된다.
- 반례 5: 플레이어 주변 활성 영역 밖의 자동 수급을 어떻게 성립시킬지는 §8.

### 수치 초안 (AI-008)

미정이다. 수동 채집 1회를 기준값 1.0으로 두고 노동 수급 속도를 배율(0.5)로 파생하는 원칙만 유지한다. 장비 페널티 배율은 §3.3을 따른다. 목업의 시간 값(부화·성장 9초)은 시연용이다.

## 4. 아트·렌더링 요구

기존 아트·렌더러는 모킹용이라 재사용하지 않고 버린다. 아트는 §3 컨셉이 읽히도록 새로 뽑는다. 바이옴은 타일만 보고도 구분돼야 하고, 위험(추위·포자 독 등)은 화면에서 바로 보여야 하며, 보스와 유닛은 모자 하나로 구분돼야 한다.

- 복셀 월드: 청크 메시 + 면별 음영·AO로 입체감, 거리 안개.
- 캐릭터: 빌보드 스프라이트. 3D에서 시점이 돌기 때문에 SVG 메시 한 장이 아니라 **앞 / 앞 3/4 / 옆 / 뒤 4방향** 그림을 만들고 오른쪽은 좌우 반전한다. 방향 선택은 8방향 각도로 한다. **동작은 통짜 포즈 그림**(준비·젖힘·내지름 등 8프레임)을 프레임으로 교체해 만들고, **표정만 교체 부품**으로 얹는 혼합 방식이다. 몸·껍질·장식을 전부 부품으로 조립하는 방식은 바위 병아리·뿌리에서는 됐지만 달팽이처럼 껍질이 몸 앞뒤로 겹치는 종은 품질이 떨어져 게임에 쓰지 않는다(연구로만 남김). 통짜 포즈는 ChatGPT 생성량이 늘지만 품질이 안정적이라 이쪽을 택했다.
- **표정은 몸과 분리한 교체 부품**으로 만든다(통짜 포즈의 얼굴 위에 덮는다).
- **캐릭터 시트가 SSOT**이고 스프라이트(애니메이션) 시트는 파생이다. 캐릭터 시트(규칙·팔레트·소켓·클립 정의)는 직접 코드로 만들고, AI 이미지 도구(ChatGPT, 한도 때문에 아껴 쓴다)는 그 시트를 참고용으로만 보고 최종 그림을 그린다. 한 시트에 여러 항목을 묶어 생성 횟수를 줄인다.
- 스타일: 단순하고 귀엽고 캐주얼한 도형 기반, 굵고 균일한 짙은 갈색 외곽선, 단색 채움. 사실적인 질감은 쓰지 않는다. 품질 기준은 상용이며 중간 품질의 임시 그림은 만들지 않는다(임시가 필요하면 원 + 표정).
- 표현은 시뮬레이션 상태를 **읽기만** 한다. 렌더·VFX가 자원·피해·위치를 만들지 않는다.

완료한 시트(바위 병아리): 4방향 턴어라운드, 성장 줄(알 · 새끼 · 등급 1~4), 표정 6종, 몸 시트, 표정 부품 시트, 껍질 시트, 광석·왕관 시트, 공격·스킬 동작 시트. 뿌리와 버섯 달팽이: 4방향 턴어라운드, 성장 줄, 공격·스킬 동작 시트와 보스 모자 시트(표정 부품 시트는 아직). 버섯 달팽이는 눈 위치·크기 지적으로 세 번 다시 뽑았다(v3 기준). 투명 처리용 단색 배경 시트에서 밝은 빛 효과가 있으면 배경 제거가 몸까지 지우므로 "큰 빛·후광 없이 작은 효과만"을 지시하고 모든 프레임을 어두운 배경에 합성해 확인한다. 원본 PNG는 아직 받지 못해 캡처로 시험했다(§8).

## 5. 결정론·락스텝 계약 (처음부터의 전제)

**원칙: 시뮬레이션 상태와 그 갱신식에는 부동소수가 없다.** 결정론을 "부동소수가 대체로 같게 나온다"에 맡기지 않고, 같은 정수 입력이 같은 정수 결과를 내는 구조로 만든다. 부동소수는 표현(렌더·UI·VFX)에서만 쓰고, 시뮬레이션이 표현의 값을 읽지 않는다.

현재 확인한 사실(as-is): 락스텝(`profiles.lockstep`, 30 TPS)과 주기적 체크섬이 있고 동일 PC 2인 RTC에서 공통 틱 해시가 일치했다. 그러나 시뮬레이션이 `rapier3d-deterministic-compat 0.21.0`(float) 위에 있고(`world.step`·`castRay`·`setLinvel` 등 약 30개 호출처), 위치·속도·피해 계산이 `CFG`의 소수(m 단위)다. 이 구조는 위 원칙에 맞지 않으므로 교체 대상이다.

규칙:

1. **수 표현:** 위치·속도·거리·시간은 정수 고정소수(Q10: 1 m = 1024 단위, GameKit `deterministic.fixedPoint`)나 정수 틱으로 둔다. int32 범위를 매 연산에서 검증한다. 소수 상수는 설정 로드 시 한 번 `fromNumber`로 변환하며, 갱신식에는 쓰지 않는다.
2. **물리:** 복셀 월드는 격자라서 충돌을 정수로 풀 수 있다. 플레이어·유닛·투사체는 고정소수 AABB와 복셀 충돌(축별 이동 후 해소)로 직접 구현한다. Rapier는 시뮬레이션에서 제거한다. 투척체 포물선도 정수 중력 가산으로 만든다.
3. **수학:** 제곱근·삼각함수·`atan2`는 쓰지 않는다. 거리 비교는 제곱 거리, 방향은 정수 벡터/방향 테이블, 길이는 정수 제곱근(뉴턴법)을 쓴다. GameKit `fixedPoint`에는 덧셈·뺄셈·곱셈·나눗셈만 있어 제곱근과 방향 테이블은 **공통 모듈 개선 대상**이다(AI-009: 최소 재현 후 GameKit에 추가 → 버전 반영 → 게임 적용).
4. **시간·난수:** 시뮬레이션은 틱의 함수다. 시각·`Date.now`·프레임 dt를 쓰지 않는다. 난수는 시드 PRNG(`SeededPRNG`)만 쓰고 상태를 스냅샷에 포함한다. 알 드롭·보스 패턴 선택도 시드 PRNG로 한다.
5. **자동화:** 노동 유닛과 농장 시설은 격자 칸·정수 좌표·틱 카운터의 이산 상태기계다. 물리 바디를 두지 않는다. 경로 탐색은 틱당 예산을 두고 라운드 로빈으로 분산한다(AI-012). 부화·성장·합성 타이머도 틱 카운터다.
6. **경로 단일화:** 단독 플레이도 1인 락스텝 세션이다. 입력은 인코딩된 명령으로만 시뮬레이션에 들어간다.
7. **소유권:** 개체·알·농장 칸·보관함의 생성/수정 주체는 `Simulation` 한 곳이다(DEV-001). 다른 참가자 소유 개체 명령은 거부하고, 공유 칸 충돌은 틱 순서·참가자 ID 순으로 판정한다.
8. **표현 보간:** 렌더는 시뮬레이션의 정수 상태를 읽어 float로 보간한다. 역방향(렌더 값 → 시뮬레이션)은 없다.
9. **검증:** 슬라이스마다 ① 같은 시드·입력 두 번 실행 시 체크섬 일치, ② 2인 RTC에서 체인 구동 중 공통 틱 해시 일치, ③ 저장 → 복원 후 같은 입력의 같은 결과, ④ 시뮬레이션 소스에서 `Math.sin|cos|atan2|sqrt|random`·`Date.now`·소수 리터럴 사용을 정적 검사로 막는다. 서로 다른 브라우저·OS 간 실제 비교는 별도 검증 범위로 기록한다(미확인).

### 이 원칙이 바꾸는 것 (as-is → to-be)

```text
as-is: Rapier(float) 월드 ── step ──▶ 위치/속도(float, m) ──▶ 체크섬
       노동 동료 = Rapier 바디
to-be: 정수 AABB ── 복셀 충돌(정수 축 해소) ──▶ 위치/속도(Q10 int32) ──▶ 체크섬
       노동 유닛 = 격자 상태기계(바디 없음)
       렌더 = 정수 상태 → float 보간 (읽기 전용)
```

저장 호환: 기존 float 저장은 이 전환에서 호환하지 않는다. 게임은 미배포이므로 Breaking 부담이 없다.

## 6. 단계별 계획

순서: 컨셉 → 아트 → 모듈·렌더·정수 코어 일괄 개선 → 슬라이스. 아트가 먼저 나와야 모듈·렌더 개선의 목표 화면이 정해진다.

| 단계 | 내용 | 완료 판정 |
|---|---|---|
| 0 | 이 문서: 컨셉(§3.0) 확정 | PR 머지. 수치·단계는 가설로 명시 |
| 1 | 아트 뽑기: 3종 캐릭터 시트와 부품 시트(바위 병아리는 완료), 바이옴 타일, 위험 표현, 보스 모자, 장비 아이콘 | 사용자가 컨셉이 읽힌다고 확인 (같은 장면 캡처 비교) |
| 2 | 모듈·렌더·정수 코어 일괄: GameKit 최신화, 렌더러 교체, `fixedPoint` 보강, 복셀 AABB 물리, Rapier 제거, 정적 검사 | 기존 이동·채굴·점프·수영·전투 재현, 같은 입력 체크섬 일치, 2인 RTC 해시 일치, 임시 렌더러 삭제 |
| 3 | 수직 슬라이스: 바이옴 2개 + 거점·농장 + 장비 페널티 + 보스 1마리 + 순환 자원 요구 1개 | §3 정상·반례 사례를 E2E로 재현, 결정론 검증 4종 |
| 4 | 바이옴·보스·유닛 확장, 자동 수급 체인(농장 시설) | 슬라이스 플레이 후 재미 판단을 근거로 범위 확정 |

3단계에서 "재미없음"이 관찰되면 §3을 수정하며 코드보다 문서를 먼저 고친다.

## 7. 소통 방식

기획은 문서가 아니라 클릭 가능한 목업(한 페이지에 탭으로 통합)으로 합의하고, 합의가 쌓이면 이 문서를 한 번에 갱신한다. 선택지는 A/B로 제시하고 추천을 앞에 둔다.

## 8. 열린 질문

- 농장 시설: 종류(예: 자동 채집, 먹이 생산, 부화 가속), 비용, 건설 방식, 보관함 용량. 자동화의 실제 형태가 여기서 결정된다.
- 노동의 종류: 지금 목업은 먹이와 광석을 한꺼번에 모은다. 작업 종류를 나눌지.
- 보스 보상: 왕관과 재료 외에 무엇을 줄지. 왕관의 정확한 쓰임.
- 월드 반경과 바이옴 조각 배치 방식(3.5 ②): 걸어서 몇 분이 적당한지, 시드 배치 규칙.
- 페널티 강도(3.3): 배율이 적당한지, 장비 없이 도전하는 플레이를 어디까지 허용할지.
- 가방과 거점 보관함의 구분: 들고 다니는 한도, 노동 유닛이 모은 자원의 운반 방식.
- 플레이어 주변 활성 영역 밖의 자동 수급을 어떻게 성립시킬지(로드 중에만 진행 / 방문 시 경과 틱 일괄 계산). 결정론과 맞아야 한다.
- 뿌리와 버섯 달팽이의 표정 부품 시트와 종별 스킬 이펙트. 세 종의 눈 크기·얼굴 톤 통일(현재 뿌리는 작은 점, 바위 병아리는 중간, 달팽이는 작은 점).
- 아트 형식 정합: 이 저장소 지침은 벡터 원본 SVG를 빌드 없이 그대로 배포하고 SVG를 빌드로 텍스처로 굽는 것을 금지한다. 새 아트는 저작한 래스터 스프라이트 시트이므로, 원본 PNG를 저장소에 그대로 두는 방식이 지침과 맞는지 확인하고 지침을 갱신해야 한다.
