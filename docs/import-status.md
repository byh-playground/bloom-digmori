# 초기 이관 기록

사용자가 로컬로 저장한 `bloom_sandbox_0.25.0_caves_dungeons_rpg.html`을 읽고 이관했다. 파일 크기는 419318 bytes, SHA-256은 `301665237112a077a26df26f7ff0c6f81a875e47e0ad9f86d30f37da86a09d63`이다.

초기 Library 자동 전송은 helper의 도구 탐색에서 실패했고, 공식 직접 전송은 Windows os.setxattr 미지원으로 실패했다. 도구 수정·메타데이터 생략·URL 우회 없이 중단했다. 이후 사용자가 직접 다운로드한 로컬 파일을 명시해 차단이 해소됐다. 다른 환경의 경로를 PC 파일로 취급하지 않았다.

## 변경 범위

- 원본 단일 HTML을 17개 기능 소스 조각, HTML 틀, 11개 CSS로 분리했다. 모듈 조각을 원래 순서로 합친 바이트가 원본 스크립트와 일치함을 확인한 후 브랜딩을 적용했다.
- 표시 이름·내보내기 파일 접두어를 Digmori로 정리했다. IndexedDB/설정 키, .bloom 확장자, 네트워크 호환 식별자 및 원본 내부 window.Bloom 참조를 유지했다.
- 원본 진단창의 0.23.1/0.21.0 잔존 표기를 core의 게임/snapshot 버전에서 빌드 시 생성하도록 수정했다.
- 소스 ZIP은 확보하지 않았고 원본 Python 빌더를 추정 복제하지 않았다. 실제 받은 HTML을 무손실 분리해 Node 빌더로 단일 HTML을 생성한다.
- 원본 GameKit dist SHA와 각 모듈 해시를 그대로 사용한다. 단독 플레이의 5개 모듈이 실제 CDN에서 HTTP 200·해시 일치하는지 검증했다.
- 신규 게임 기능, 저장 변환 어댑터, 불필요한 게임 로직 변경은 없다.

## 검증 기록

실제 Edge의 고정 사용자 흐름과 SDK 응답 결과는 verification-initial.json에 기록한다. 입력 전용 Playwright E2E가 게임 상태를 관측하며 물리·SDK 대체물이나 상태 주입 fixture를 사용하지 않는다. 최초 탐색 검증에서 포인터 잠금 획득 클릭 직후 공격이 끝나기 전에 채굴해 미채굴을 관측했고, 공격 종료 후 자연 입력으로 확인했다. 합성 Escape는 브라우저 포인터 잠금을 해제하지 않아 가방 E의 실제 UI 경로로 잠금을 해제했다. 제품 코드를 우회하거나 이 동작을 임의 수정하지 않았다.

원본 보고는 GameKit 시험용 API를 사용했으므로 실제 SDK 실행 근거로 취급하지 않았다. 이전 실패 CI는 원본이 없던 Draft 준비 커밋의 결과이며 최종 PR 검증과 구분한다.
