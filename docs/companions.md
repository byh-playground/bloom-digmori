# 동료 노동과 전투 · 0.28.5

시작 지점에서 **K / 동료**를 열어 말랑조개와 칼잎새 카드의 **함께하기**를 누른다. 같은 두 동료를 거점 작업·대기·전투 사이에서 옮긴다. 새 자원이나 화폐는 없다.

## 거점 화면

**동료 / 작업 / 보관함**을 탭으로 바로 선택한다. 위의 전투 세 슬롯은 어느 탭에서도 보이며, 카드와 슬롯은 같은 실제 배치를 표시한다.

- **동료:** 카드 탭 → 첫 빈 전투 슬롯 장착. 장착 카드나 위 슬롯 탭 → 해제. 이미 쓰는 슬롯을 덮어쓰지 않는다. 카드 아래 **작업 보내기 / 작업 회수**로 탭을 왕복하지 않고 작업을 바꿀 수 있다.
- **작업:** 카드 탭 → 거점 작업 보내기 / 작업 회수. 채집할 자원 종류와 이동·채집·운반 상태를 읽고, 아래 **전투 장착**으로 바로 전환할 수 있다.
- **보관함:** 실제 아홉 칸의 아이템·수량과 사용 칸 수를 확인하고 **가방으로 가져오기**로 수령한다. 높이가 충분한 화면은 다른 탭에서도 아래 **자원 받기**로 바로 수령할 수 있다. 멀리 있거나 비어 있으면 이유를 표시한다. 가방에 못 담은 자원은 보존한다.
- **상세:** 역할·피해·재사용·회수 규칙은 별도 보기에서 읽는다. 닫기·재열기에도 보고 있던 탭·카드·상세와 포커스를 유지한다. Esc / K / 닫기로 게임에 돌아온다. 자주 쓰는 배치·회수에 확인 팝업은 없다.

화면 높이가 충분한 390×844와 가로 844×390은 두 카드를 함께 표시한다. 짧고 좁은 화면은 동료 이름 버튼으로 한 장씩 전환한다. 주요 버튼의 최소 높이는 44px이며, 390×844와 844×390의 편성·작업·보관함은 창 내부 스크롤 없이 조작한다. 긴 상세 설명은 별도 영역에서 스크롤할 수 있다. 세로 화면의 **동료 관리**로도 접근한다.

기준은 [Bloom UI/UX P2·P4·P6·P9](https://github.com/byh-playground/bloom-reference/blob/a7e9d94ccc8fbaed06d66865d6348d1cf6211753/rules/visual-ux.html)와 [Bounko의 직접 분류·동행 슬롯](https://github.com/byh-playground/bloom-bounko/blob/987e3e92f6dee629f21f0e100fba21bb1715b088/index.html)이다. 독립적인 두 동료에는 성장 관계 트리를 만들지 않고, 분류·요약 카드·상세 분리와 첫 빈 슬롯 조작을 적용한다.

## 플레이 흐름

- **거점 작업:** 시작 거점 7m 안에서 배치한다. 동료는 4m 주변의 노출된 기초 자원을 채집하고 실제 드롭을 들어 9칸 거점 보관함으로 운반한다. 조개는 흙·풀·잎·버섯류, 잎새는 나무·잎·풀·버섯류를 다룬다. 희귀 광석과 작업대·던전 상자는 작업 대상이 아니다. 거점 바로 아래 바닥도 남긴다.
- **보관함:** 거점 근처에서 `가방으로 가져오기`를 누른다. 기존 인벤토리 스택 한도를 따른다. 가방·보관함이 가득 차면 남은 수량을 원래 위치에 보존한다.
- **다중 장착:** 세 슬롯에 서로 다른 동료를 배치한다. Z/X/C 또는 화면 슬롯으로 사용할 동료를 고른다. 선택한 동료가 손으로, 나머지는 몸의 다른 앵커로 옮겨 붙는다. `손도구`나 단축바를 누르면 기존 도구·무기로 돌아간다.
- **공형 조개:** 기존 공격 입력으로 준비 후 발사한다. 실제 Rapier 발사체로 공통 피해 판정을 거쳐 돌아온다. 재사용 대기 1.6초이며 복귀 전에는 다시 발사하지 못한다.
- **생물 검:** 같은 공격·차지 입력과 공통 근접 스윕·기력·피해 경로를 사용한다. 재사용 대기 1초이며 얼굴과 잎 몸체가 준비·타격·회복에 맞춰 반응한다. 모바일 화면 탭·길게 누르기도 같다.
- **회수:** 운반·발사 중 배치를 바꾸면 자원을 내려놓거나 손으로 복귀한 뒤 반영한다. 비행 중 회수는 기존 발사체를 한 번 제거한다. 슬롯이 복귀 도중 다른 동료로 차면 안전하게 보관 상태가 된다. 사망·참가자 일시중단에는 동료를 보관 상태로 회수하며 운반 중인 자원도 동료 데이터에 남는다. 거점에서 가방으로 수령할 수 있다.

## 상태·저장·멀티 계약

`Simulation.companions`가 유일한 소유자다. 단위 데이터는 안정적인 ID, 방 참가자 소유자 ID, `reserve | work | combat` 위치, 선택적 전투 슬롯을 갖는다. 별도의 전투 동료 복제본이나 노동용 명부를 만들지 않는다. 능력 데이터는 채집·운반·공격으로 조합한다. `phase`는 현재 작업·비행·복귀의 단계이며 위치를 추가로 부여하지 않는다.

배치·획득·슬롯 선택·보관함 수령은 기존 인코딩된 명령을 통해 고정 틱에 처리한다. 다른 참가자 소유 동료의 명령은 거부한다. 노동 물리체도 기존 Rapier 월드와 지형 스트리밍을 사용한다. 채굴은 플레이어와 같은 `Simulation.harvest()`를 호출하며, 드롭을 실제로 제거해 운반 수량으로 옮긴다. 렌더·VFX는 자원이나 피해를 만들지 않는다.

공격은 `Combat.makeAction/start/tick/hit`를 사용한다. 시작할 때 동료 ID·공격자·공격 방향·피해를 고정하고, 발사체에 복사한다. 그 뒤 다른 동료를 선택해도 이미 발사된 공격의 귀속은 바뀌지 않는다. 차지·근접 준비 중 장비를 회수하면 아직 실행되지 않은 공격을 취소하고 기력을 충전하지 않는다.

동료·거점·작업 대상·운반 수량·대기 시간·비행/복귀 상태 및 물리 핸들은 기존 월드 스냅샷에 포함된다. 읽기는 원본 상태를 바꾸지 않는다. 저장 키와 snapshotVersion `0.26.0`은 유지한다. 동료 필드가 없는 기존 저장은 빈 동료 명부로 읽으며, 기존 월드·가방·물리는 그대로 복원한다. 별도 구버전 실행 엔진이나 변환 계층은 없다. 제품 버전 `0.28.5`를 기존 멀티 simulationVersion 계약에도 사용하므로 같은 버전끼리 방에 참여한다. UI는 기존 획득·배치·수령 명령을 보내고 결과를 조회하며, 동료 상태를 직접 수정하지 않는다.

협동 방은 기존 Nostr/RTC 전송·세션·명령·스냅샷으로 동기화한다. GameKit의 공식 `resume: {storage: sessionStorage}`를 사용해 같은 탭의 방 서명 ID를 보존한다. `협동 → 다시 연결`은 기존 루프·전송을 닫고 이 ID로 재입장하며 원래 개인 월드 백업도 유지한다. 정상 `나가기`와 새 참가자 신분은 재접속과 다르다. 일시중단에서 돌아온 동료는 안전한 보관 상태에서 다시 배치할 수 있다.

## 검증 명령

```sh
npm run build
npm test
npm run test:companions
npm run test:companions:rtc
```

각 E2E의 상한은 180초다. 동료 E2E는 실제 입력 획득 → 노동/운반 → 회수 → 보관함 수령 → 자동 다중 장착·해제 → 두 공격/복귀 → 저장/재시작을 확인한다. 390px 터치의 같은 거점 흐름과 844×390의 카드·슬롯·보관함, 상세 재열기·포커스와 모달 게임 입력 격리도 포함한다. 전투 대상은 기존 `?debug=1` 적 소환 UI로 제공하며 피해 로직은 제품 그대로다. RTC E2E는 공개 Nostr 릴레이와 두 Edge 컨텍스트의 실제 네이티브 데이터 채널, 소유권·자원·슬롯 동기화 및 같은 ID 재접속을 확인한다. 모의 SDK·방 전송을 사용하지 않는다. 출력은 무시되는 `artifacts/companions/`에 쓴다.

실물 휴대폰, 서로 다른 NAT 환경, 4인 전체 조합, 장시간 노동·자원 균형 및 모든 카메라/동작 조합은 별도 검증 범위다. 실행 결과와 배포 커밋은 작업 PR에 기록한다.

## 공형 발사의 기본 물리

0.28.3은 실제 Rapier 발사체였지만 공형 공격만 중력 배율이 0이었다. 0.28.4부터 발사 초기 속도는 `고정된 공격 방향 × 18m/s + 월드 위쪽 8m/s`, 중력 배율은 1이다. 따라서 기존 월드의 Y축 아래로 20m/s²를 적용받는 실제 포물선 비행이다. 별도 궤적 계산기나 렌더 곡선을 사용하지 않는다. 카메라를 위·아래로 조준하면 수평/수직 초기 속도도 그 방향에 따라 달라진다.

기존 CCD 구체의 반지름을 비행 스프라이트의 실제 윤곽 크기와 맞춘 약 0.29m로 사용한다. 적·지형의 부피 충돌은 기존 Rapier 충돌 이벤트로 처리한다. 첫 충돌에서 공격 발사체를 제거하고, 적이면 공통 피해를 한 번만 적용한다. 비접촉 시 기존 `12m / 18m/s`의 약 0.667초 발사 수명 뒤 회수한다. 스프라이트와 지면 그림자는 동일한 보간된 물리 위치 및 실제 지형 높이를 사용한다.

**복귀는 공격과 분리된 비전투 회수다.** 충돌·수명 종료·회수 요청 후 공격 콜라이더가 사라지며 복귀는 추가 피해를 주지 않는다. 복귀 표시는 기존 정책대로 지형을 통과할 수 있고, 지형에 막혀 영구적으로 장착을 잃지 않도록 손 앵커로 회수한다. 사망·연결 중단에는 기존 보관 회수 정책을 유지한다. 노동 동료의 비행 이동에는 이 공격용 중력을 적용하지 않는다.

기존 저장의 물리 스냅샷은 그대로 복원한다. 새 발사 파라미터가 없는 이전 저장의 준비 중 공격도 현재 동료 발사 설정을 사용한다. 이미 비행 중이던 이전 저장의 구체는 저장된 물리 상태로 짧은 남은 수명을 마친 뒤 회수되며, 다음 발사부터 새 기본 물리를 사용한다.
