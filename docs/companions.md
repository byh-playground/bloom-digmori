# 바이옴과 동료 목장·전투 · 0.34.0

동료는 **보스가 떨군 알에서만** 태어난다(G2 D-107). 초원의 꽃 고리(뿌리 거인), 균류 숲의 버섯 고리(포자 군주), 동굴 유적 최심부(광맥 병아리 대왕)에서 보스를 쓰러뜨리면, 플레이어마다 보스 종별 첫 처치는 알을 꼭 떨구고 그 뒤에는 35% 확률이다. 알을 들고 땅을 우클릭하면 그 자리에 놓이고 30초 뒤 놓은 사람의 아기(1등급)로 부화해 그 자리 **목장**에 머문다(0.34.0, D-103…D-106). 울타리·문으로 가두고, 땅에 던진 먹이를 세 번 먹으면 성체가 되며, 합성 물약으로 같은 종·등급 둘을 합치고, 울타리 안 보관 상자로 노동을 시킨다. 야생 개체(초원 뿌리, 균류 숲 버섯 달팽이, 동굴 바위 병아리)는 중립으로 돌아다니다 공격받으면 공격한 플레이어를 향해 반격하고, 거리가 크게 벌어지면 출현 지점으로 돌아간다. 쓰러뜨리면 자원을 떨군다.

## 자연 생성 규칙

바이옴별 규칙은 하나의 데이터 묶음에서 관리한다. 식생은 바이옴 기후·표면 재질·고도·주변 8방향의 경사·주변보다 튀어나온 정도를 모두 확인한다. 숲과 초원 나무는 풀 표면, 균류 수관은 균사 표면에서만 자란다. 서리 고원은 눈이 덮인 낮은 완경사에 드문 나무만 허용하고 고지대 암반에는 나무를 두지 않는다. 광석 편향은 바이옴 표면·기후와 지하 석재/깊이 조건을, 동굴 수정은 호스트 암석·Y 범위·기후 조건을 같은 규칙 데이터에서 읽는다. 셀 좌표와 기존 월드 시드 해시를 유지해 청크 순서와 재진입에 따라 결과가 달라지지 않는다. 저장 지형 편집을 보존하며 기존 월드 전체를 강제로 다시 만들지 않는다.

낮 야생 개체는 월드 전체 상한 6, 플레이어 반경 32m 상한 3, 생성 간격 6초다. 지표에서는 그 자리 게임 바이옴의 종이, 지하(지표 3칸 아래)에서는 동굴 바닥에 바위 병아리가 나타난다. 개체는 지면 높이·경사·머리 위 공간과 주변 플레이어/배우 간격 검사를 통과해야 나타난다. 기본 중립과 실제 피격자 타깃, 26m 이탈 시 중립 복귀는 공통 시뮬레이션 규칙으로 유지한다.

## 동료 창

동료 창(K)은 보유 개체 카드와 전투 세 슬롯만 다룬다. 0.34.0에서 거점 작업 배치(작업 탭)·거점 보관함(보관함 탭, 가방으로 가져오기, 거점 자원 회수)은 지웠다. 목장·성장·합성·노동은 메뉴 없이 월드에서 한다.

- **편성:** 위의 빈 전투 슬롯 하나를 고르고 성체 카드를 누르면 편성한다. 같은 슬롯을 고른 뒤 다른 개체를 눌러 교체하거나 **해제**를 눌러 그 자리 목장에 남긴다. 아기는 성체가 될 때까지 편성할 수 없고 카드에 먹이 진행(n/3)과 종의 먹이를 보여 준다.
- **상태:** 카드에 등급·성장 단계, 공격·노동 적성과 먹이, 현재 상태(목장에서 돌아다님·먹이로 가는 중·채집 중·상자로 운반·전투 슬롯)를 표시한다.

가로 844×390 화면은 빈 슬롯과 보유 개체 목록을 같이 표시한다. 주요 버튼의 최소 높이는 44px이다. 편성·교체·해제는 슬롯과 개체 카드를 순서대로 탭해 두 번 안에 끝나며 드래그 입력을 요구하지 않는다. PC는 같은 구조를 마우스 클릭으로 사용한다.

편성 패턴은 [Palworld 공식 게임 페이지](https://www.pocketpair.jp/en/games-en/palworld-en/)와 [공식 업데이트 사례](https://steamcommunity.com/games/1623730/announcements/detail/686383649529010624)에서 파티·보유 동료를 함께 관리하는 방식을 참고했다. 이 게임의 작은 개체 수와 작업 역할에 맞게 빈 슬롯·개체 목록으로 축약하고, 탭 기반 조작으로 구현했다.

## 플레이 흐름

- **목장(D-103):** 전투 슬롯에 없는 동료는 목장 상태다. 부화한 칸이나 슬롯에서 해제된 칸에 머물며, 칸 단위 걷기(한 칸 오르기, 세 칸까지 내려가기)로 닿는 칸만 돌아다닌다. 울타리·닫힌 문은 동료에게 1.5칸 높이라 넘지도 올라서지도 못하고, 두 칸 넘는 벽(구덩이)도 오르지 못한다. 동료 칸에서 닿는 칸을 ±16칸(33×33) · ±6칸 상자 안에서 너비 우선으로 채워 상자 밖으로 나가려 하면 열린 곳, 아니면 닫힌 목장이다. 열린 곳에서는 머문 자리 5칸 안에서만 돌아다닌다.
- **이끌기:** 종의 먹이(뿌리 열매 · 바위 병아리 씨앗 · 버섯 달팽이 잎)를 손에 들면 10칸 안의 동료가 따라온다. 이때도 걷는 칸은 같은 규칙이라 닫힌 문을 지나지 않는다.
- **성장(D-105):** 아기는 8칸 안에 던져진(Q) 자기 먹이로 걸어가 먹는다(1.2초). 세 번이면 성체(1등급)다.
- **합성(D-104):** 합성 물약(공명 수정 조각 + 열매)을 우클릭으로 던지면 처음 닿는 곳에서 반경 3m로 터진다. 맞은 내 성체를 종·등급으로 묶어 유닛 번호 순으로 둘씩 합치고, 번호가 작은 쪽이 등급 +1(최대 4)이 된다.
- **상자 노동(D-106):** 닫힌 목장 안에 보관 상자가 있으면 그 목장의 성체가 동료 높이의 적성 블록(뿌리 풀흙·흙·원목·잎, 바위 병아리 돌·조약돌·광석, 버섯 달팽이 버섯 갓·줄기·균사 흙)을 캐서 드롭 하나를 상자로 나른다. 캐도 목장이 열리지 않는 블록만 캔다. 캔 블록은 20초 뒤 그 자리에 다시 자란다. 상자가 가득 차면 짐을 든 채 기다린다.
- **다중 장착:** 세 슬롯에 서로 다른 개체 ID를 배치한다. Z/X/C 또는 화면 슬롯으로 사용할 동료를 고른다. 단축바를 누르면 기존 도구·무기로 돌아간다.
- **바위 병아리 투척:** 기존 공격 입력으로 준비한 뒤 실제 Rapier 구체를 포물선으로 던진다. 첫 적 명중은 공통 피해 판정을 한 번 적용하고, 지면에 착지해 약 0.3초 멈춘 뒤 회수된다. 재사용 대기 1.6초다.
- **회수:** 투척 중 배치를 바꾸면 착지·복귀를 마친 뒤 반영한다. 사망·참가자 일시중단에는 발사체를 취소하고 전투 동료는 슬롯을 지킨 채 주인에게 돌아오며, 목장 동료는 그 자리에 남는다.

## 상태·저장·멀티 계약

`Simulation.companions`가 유일한 소유자다. 단위 데이터는 안정적인 개체 ID, 방 참가자 소유자 ID, `ranch | combat` 위치, 선택적 전투 슬롯, 목장 걷기 상태(정수 칸·다음 칸·걸음 틱·경로·할 일·대기 틱·머문 칸)를 갖는다. 목장 동료에는 물리 바디가 없다. 종을 슬롯에 고정하지 않고 보유 개체를 단일 ID로 추적한다. 같은 종을 여러 번 보유할 수 있지만 중복 ID와 한 개체의 이중 배치를 허용하지 않는다. 별도의 전투 동료 복제본이나 노동용 명부를 만들지 않는다. 능력 데이터는 채집·운반·공격으로 조합한다. `phase`는 현재 작업·비행·착지 체류·복귀의 단계이며 위치를 추가로 부여하지 않는다.

배치·슬롯 선택은 기존 인코딩된 명령으로, 울타리·문·상자·먹이·물약은 일반 설치·사용·던지기 입력으로 고정 틱에 처리한다. 다른 참가자 소유 동료의 명령은 거부한다. 노동 채굴은 플레이어와 같은 `Simulation.harvest()`를 호출하며, 드롭을 실제로 제거해 운반 수량으로 옮긴다. 렌더·VFX는 자원이나 피해를 만들지 않는다.

공격은 `Combat.makeAction/start/tick/hit`를 사용한다. 동료의 고정 공격 프로필에서 사거리·피해를 조회하므로 가방에서 선택한 무기가 동료 공격에 섞이지 않는다. 모든 기본 공격에는 기존 RPG `might` 보너스가 적용된다. 시작할 때 동료 ID·공격자·공격 방향·피해를 고정하고, 투척체에 복사한다. 그 뒤 다른 동료를 선택해도 이미 시작된 공격의 귀속은 바뀌지 않는다. 집게 준비 중 회수하면 실행되지 않은 공격을 취소한다.

동료·야생·보스 배우·놓인 알·보관 상자 내용·다시 자랄 블록·작업 대상·운반 수량·대기 시간·비행/착지 체류/복귀 상태 및 물리 핸들은 기존 월드 스냅샷에 포함된다. 투척 피해가 확정된 발사체는 `spent` 상태로 저장되어 재접촉해도 다시 피해를 주지 않는다. 읽기는 원본 상태를 바꾸지 않는다. 저장 키와 snapshotVersion `0.26.0`은 유지한다. 동료 데이터가 없는 기존 저장은 그대로 빈 목록으로 복원하고, 이미 저장된 지형 편집도 유지한다. 지형 전체 강제 재생성은 하지 않으며 별도 마이그레이션 계층을 추가하지 않는다. 제품 버전 `0.28.7`을 기존 멀티 simulationVersion 계약에도 사용하므로 같은 버전끼리 방에 참여한다. UI는 기존 획득·배치·수령 명령을 보내고 결과를 조회하며, 동료 상태를 직접 수정하지 않는다.

협동 방은 기존 Nostr/RTC 전송·세션·명령·스냅샷으로 동기화한다. GameKit의 공식 `resume: {storage: sessionStorage}`를 사용해 같은 탭의 방 서명 ID를 보존한다. `협동 → 다시 연결`은 기존 루프·전송을 닫고 이 ID로 재입장하며 원래 개인 월드 백업도 유지한다. 정상 `나가기`와 새 참가자 신분은 재접속과 다르다. 일시중단에서 돌아온 동료는 안전한 보관 상태에서 다시 배치할 수 있다.

## 검증 명령

```sh
npm test
npm run test:companions
npm run test:companions:rtc
```

각 E2E의 상한은 180초다. 동료 E2E는 같은 시드 청크 결정론, 낮의 중립 야생 개체, 실제 공격자 타깃, 보스 처치 → 알 → 제작대 제작(울타리·문·상자·물약) → 울타리 목장 설치·문 열고 닫기 → 놓기 → 부화 → 먹이 3번 → 성체(두 마리) → 합성 물약 → 2등급 → 상자 노동·재생 → 저장 재진입 → 목장 이탈 없음, 옛 거점 저장 이전, 빈 슬롯 편성·해제, PC와 가로 모바일 저장 재진입, 바위 병아리 투척 착지·회수, 뿌리 근접 공격을 확인한다. 모바일 패널과 주요 버튼은 가로 844×390 화면에서 맞는지 확인한다. RTC E2E는 두 Edge 컨텍스트로 공개 Nostr 시그널링과 네이티브 데이터 채널을 사용해 야생 반격 타깃, 동료 상태 동기화, 소유권 거부, 양방향 RTC 데이터와 같은 참가자 ID 재접속을 확인한다. SDK나 방 전송을 모의하지 않는다. 출력은 무시되는 `artifacts/companions/`에 쓴다.

실물 휴대폰, 서로 다른 NAT 환경, 4인 전체 조합, 장시간 노동·자원 균형 및 모든 카메라/동작 조합은 별도 검증 범위다.

## 공형 발사의 기본 물리

0.28.3은 실제 Rapier 발사체였지만 공형 공격만 중력 배율이 0이었다. 0.28.4부터 발사 초기 속도는 `고정된 공격 방향 × 18m/s + 월드 위쪽 8m/s`, 중력 배율은 1이다. 따라서 기존 월드의 Y축 아래로 20m/s²를 적용받는 실제 포물선 비행이다. 별도 궤적 계산기나 렌더 곡선을 사용하지 않는다. 카메라를 위·아래로 조준하면 수평/수직 초기 속도도 그 방향에 따라 달라진다.

기존 CCD 구체의 반지름을 비행 스프라이트의 실제 윤곽 크기와 맞춘 약 0.29m로 사용한다. 적·지형의 부피 충돌은 기존 Rapier 충돌 이벤트로 처리한다. 첫 적 접촉은 공통 피해를 한 번만 적용한다. `spent` 발사체는 실제 탄도를 따라 계속 낙하하며, 비접촉 시 기존 `12m / 18m/s`의 약 0.667초 발사 수명부터도 낙하가 계속된다. 지형 지원면에서 2틱 연속 확인되면 접촉점에 멈춰 약 0.3초 머문 뒤 회수한다. 스프라이트와 지면 그림자는 동일한 보간된 물리 위치 및 실제 지형 높이를 사용한다.

**복귀는 공격과 분리된 비전투 회수다.** 첫 적 접촉에서 공격 콜라이더는 피해 1회를 확정하고 `spent`가 된다. 지형 접촉이나 사거리 종료로 빗나가도 실제 탄도와 낙하를 계속하며, 지형에 착지하면 접촉점에서 속도·중력을 멈춰 약 0.3초 머문다. 이후 발사체 물리체를 제거하고 동료를 원래 선택자의 앵커로 회수한다. 착지 전 배치 변경은 이 순서를 건너뛰지 않고, 복귀는 추가 피해를 주지 않는다. 사망·연결 중단에는 기존 보관 회수 정책을 유지한다. 노동 동료의 이동에는 이 공격용 중력을 적용하지 않는다.

기존 저장의 물리 스냅샷은 그대로 복원한다. 새 발사 파라미터가 없는 이전 저장의 준비 중 공격도 현재 동료 발사 설정을 사용한다. 이미 비행 중이던 이전 저장의 구체는 저장된 물리 상태로 짧은 남은 수명을 마친 뒤 회수되며, 다음 발사부터 새 기본 물리를 사용한다.
