# 바이옴과 동료 노동·전투 · 0.28.12

낮에 세계를 탐험하면 지형에 안전하게 나타난 중립 동료 후보를 발견할 수 있다. 실제 후보에 가까이 다가가 **K / 동료** 또는 화면의 동료 관리 버튼을 열고 **함께하기**를 누르면 그 개체 ID를 보유 목록에 추가한다. 공격받은 후보는 공격한 플레이어를 향해 반격하며, 거리가 크게 벌어지면 자기 출현 지점으로 돌아간다. 밤 적대 몹의 표적 선택과는 별도 규칙이다.

## 자연 생성 규칙

바이옴별 규칙은 하나의 데이터 묶음에서 관리한다. 식생은 바이옴 기후·표면 재질·고도·주변 8방향의 경사·주변보다 튀어나온 정도를 모두 확인한다. 숲과 초원 나무는 풀 표면, 균류 수관은 균사 표면에서만 자란다. 서리 고원은 눈이 덮인 낮은 완경사에 드문 나무만 허용하고 고지대 암반에는 나무를 두지 않는다. 광석 편향은 바이옴 표면·기후와 지하 석재/깊이 조건을, 동굴 수정은 호스트 암석·Y 범위·기후 조건을 같은 규칙 데이터에서 읽는다. 셀 좌표와 기존 월드 시드 해시를 유지해 청크 순서와 재진입에 따라 결과가 달라지지 않는다. 저장 지형 편집을 보존하며 기존 월드 전체를 강제로 다시 만들지 않는다.

낮 야생 후보는 실제 탐색에서 더 자주 보이도록 월드 전체 상한을 4→6, 플레이어 반경 28→32m의 상한을 2→3, 생성 간격을 8→6초로 조정했다. 후보는 지면 높이·경사·머리 위 공간과 주변 플레이어/배우 간격 검사를 통과해야 나타난다. 기본 중립과 실제 피격자 타깃, 26m 이탈 시 중립 복귀는 공통 시뮬레이션 규칙으로 유지한다.

## 거점 화면

**동료 / 작업 / 보관함**을 탭으로 바로 선택한다. 위의 전투 세 슬롯은 어느 탭에서도 보이며, 카드와 슬롯은 같은 실제 배치를 표시한다.

- **동료:** 위의 빈 전투 슬롯 하나를 고르고 보유 개체 카드를 누르면 편성한다. 같은 슬롯을 고른 뒤 다른 개체를 눌러 교체하거나 **해제**를 한 번 눌러 보관으로 돌려보낸다. 종별 고정 자리는 없고, 중복 종의 서로 다른 개체 ID도 각각 편성할 수 있다. 카드에는 공격·채집 호환 능력을 함께 표시한다. 카드 아래 **거점 작업 배치 / 작업 회수**로 탭을 왕복하지 않고 작업을 바꿀 수 있다.
- **주변 후보:** 후보 카드에서 이름·거리·중립/반격 상태를 확인하고, 가까이 다가가 **함께하기**를 누른다. 동료는 플레이어와 즉시 겹치지 않고 평탄한 지면에 나타난다. 개체 수는 플레이어별·월드 전체 상한을 둔다.
- **작업:** 카드의 **거점 작업 배치 / 작업 회수**를 누른다. 채집할 자원 종류와 이동·채집·운반 상태를 읽고, 아래 전투 편성 동작으로 바로 전환할 수 있다. 보관함이 가득 차면 한 개 운반물을 보존한 채 작업을 멈추고, 수거 대기 상태를 표시한다.
- **보관함:** 실제 아홉 칸의 아이템·수량과 사용 칸 수를 확인하고 **가방으로 가져오기**로 수령한다. 높이가 충분한 화면은 다른 탭에서도 아래 **자원 받기**로 바로 수령할 수 있다. 멀리 있거나 비어 있으면 이유를 표시한다. 가방에 못 담은 자원은 보존한다.
- **상태:** 개체 카드에서 공격·채집 호환 능력, 현재 배치와 진행 상태를 바로 읽는다. 닫기·재열기에도 현재 탭과 포커스를 유지한다. Esc / K / 닫기로 게임에 돌아온다. 자주 쓰는 배치·회수에 확인 팝업은 없다.

가로 844×390 화면은 빈 슬롯과 보유 개체 목록을 같이 표시한다. 주요 버튼의 최소 높이는 44px이다. 편성·교체·해제는 슬롯과 개체 카드를 순서대로 탭해 두 번 안에 끝나며 드래그 입력을 요구하지 않는다. PC는 같은 구조를 마우스 클릭으로 사용한다.

편성 패턴은 [Palworld 공식 게임 페이지](https://www.pocketpair.jp/en/games-en/palworld-en/)와 [공식 업데이트 사례](https://steamcommunity.com/games/1623730/announcements/detail/686383649529010624)에서 파티·보유 동료를 함께 관리하는 방식을 참고했다. 이 게임의 작은 개체 수와 작업 역할에 맞게 빈 슬롯·개체 목록으로 축약하고, 탭 기반 조작으로 구현했다.

## 플레이 흐름

- **거점 작업:** 시작 거점 7m 안에서 배치한다. 동료는 4m 주변의 노출된 기초 자원을 채집하고 실제 드롭을 들어 9칸 거점 보관함으로 운반한다. 조약돌 두더지는 흙·풀·잎·버섯류, 수확집게는 나무·잎·풀·버섯류를 다룬다. 희귀 광석과 작업대·던전 상자는 작업 대상이 아니다. 거점 바로 아래 바닥도 남긴다.
- **보관함:** 거점 근처에서 `가방으로 가져오기`를 누른다. 기존 인벤토리 스택 한도를 따른다. 가방·보관함이 가득 차면 남은 수량을 원래 위치에 보존한다.
- **다중 장착:** 기존 세 슬롯에 서로 다른 개체 ID를 배치한다. 종이 같은 개체도 중복 편성할 수 없고, 한 ID는 전투·작업·보관 중 한 곳에만 놓인다. Z/X/C 또는 화면 슬롯으로 사용할 동료를 고른다. 동료는 공격할 때만 전투 장면에 나타나며 손·등에 상시 붙지 않는다. `손도구`나 단축바를 누르면 기존 도구·무기로 돌아간다.
- **조약돌 두더지 투척:** 기존 공격 입력으로 준비한 뒤 실제 Rapier 구체를 포물선으로 던진다. 첫 적 명중은 공통 피해 판정을 한 번 적용하고, 빗나가면 사거리 종료 뒤 계속 낙하한다. 투척체는 지면에 착지해 약 0.3초 멈춘 뒤 회수되며 공중에서 즉시 돌아오지 않는다. 재사용 대기 1.6초이고 착지·회수 중에는 다시 던질 수 없다.
- **조약돌 두더지 박치기:** 거점 채집 단계마다 자원 블록을 향해 몸을 젖혔다가 머리와 코로 들이받고 반동하는 짧은 동작을 반복한다. 각 타격 프레임은 실제 채집 진행률에 맞춰 움직이며, 타깃 제거와 자원 회수는 기존 시뮬레이션 판정으로 처리한다.
- **수확집게:** 같은 기본 공격·차지 입력을 사용한다. 수확집게가 잠깐 나타나 몸을 낮추고 집게를 벌린 뒤 팔을 전진해 실제 집게 끝으로 접촉하며 닫고, 풀고 당겨지며 사라진다. 피해 판정은 애니메이션과 같은 12프레임 자세에서 집게 끝을 쓸며, 한 동작에서 대상마다 한 번만 맞는다. 재사용 대기 1초다.
- **회수:** 운반 중 배치를 바꾸면 운반을 마치거나 보관함이 가득 찬 상태로 자원을 보존한 뒤 반영한다. 투척 중에는 발사체를 공중에서 제거하지 않고 착지·잠깐 대기까지 마친 뒤 회수한다. 복귀 중 슬롯이 다른 동료로 차면 기존 동료를 해제하지 않고 안전하게 보관한다. 사망·참가자 일시중단에는 공격 발사체를 취소하고 동료와 운반 자원을 보관 상태로 회수한다. 거점에서 가방으로 수령할 수 있다.

## 상태·저장·멀티 계약

`Simulation.companions`가 유일한 소유자다. 단위 데이터는 안정적인 개체 ID, 방 참가자 소유자 ID, `reserve | work | combat` 위치, 선택적 전투 슬롯을 갖는다. 종을 슬롯에 고정하지 않고 보유 개체를 단일 ID로 추적한다. 같은 종을 여러 번 보유할 수 있지만 중복 ID와 한 개체의 이중 배치를 허용하지 않는다. 별도의 전투 동료 복제본이나 노동용 명부를 만들지 않는다. 능력 데이터는 채집·운반·공격으로 조합한다. `phase`는 현재 작업·비행·착지 체류·복귀의 단계이며 위치를 추가로 부여하지 않는다.

배치·획득·슬롯 선택·보관함 수령은 기존 인코딩된 명령을 통해 고정 틱에 처리한다. 다른 참가자 소유 동료의 명령은 거부한다. 노동 물리체도 기존 Rapier 월드와 지형 스트리밍을 사용한다. 채굴은 플레이어와 같은 `Simulation.harvest()`를 호출하며, 드롭을 실제로 제거해 운반 수량으로 옮긴다. 렌더·VFX는 자원이나 피해를 만들지 않는다.

공격은 `Combat.makeAction/start/tick/hit`를 사용한다. 동료의 고정 공격 프로필에서 사거리·차지 단계·피해·기력을 조회하므로 가방에서 선택한 무기가 동료 공격에 섞이지 않는다. 모든 기본 공격에는 기존 RPG `might` 보너스가 적용된다. 시작할 때 동료 ID·공격자·공격 방향·피해를 고정하고, 투척체에 복사한다. 그 뒤 다른 동료를 선택해도 이미 시작된 공격의 귀속은 바뀌지 않는다. 차지·집게 준비 중 회수하면 실행되지 않은 공격을 취소하고 기력을 충전하지 않는다.

동료·후보 배우·거점·작업 대상·운반 수량·대기 시간·비행/착지 체류/복귀 상태 및 물리 핸들은 기존 월드 스냅샷에 포함된다. 투척 피해가 확정된 발사체는 `spent` 상태로 저장되어 재접촉해도 다시 피해를 주지 않는다. 읽기는 원본 상태를 바꾸지 않는다. 저장 키와 snapshotVersion `0.26.0`은 유지한다. 동료 데이터가 없는 기존 저장은 그대로 빈 목록으로 복원하고, 이미 저장된 지형 편집도 유지한다. 지형 전체 강제 재생성은 하지 않으며 별도 마이그레이션 계층을 추가하지 않는다. 제품 버전 `0.28.7`을 기존 멀티 simulationVersion 계약에도 사용하므로 같은 버전끼리 방에 참여한다. UI는 기존 획득·배치·수령 명령을 보내고 결과를 조회하며, 동료 상태를 직접 수정하지 않는다.

협동 방은 기존 Nostr/RTC 전송·세션·명령·스냅샷으로 동기화한다. GameKit의 공식 `resume: {storage: sessionStorage}`를 사용해 같은 탭의 방 서명 ID를 보존한다. `협동 → 다시 연결`은 기존 루프·전송을 닫고 이 ID로 재입장하며 원래 개인 월드 백업도 유지한다. 정상 `나가기`와 새 참가자 신분은 재접속과 다르다. 일시중단에서 돌아온 동료는 안전한 보관 상태에서 다시 배치할 수 있다.

## 검증 명령

```sh
npm run build
npm test
npm run test:companions
npm run test:companions:rtc
```

각 E2E의 상한은 180초다. 동료 E2E는 같은 시드 청크 결정론, 고도·경사 식생 조건, 낮의 중립 후보, 실제 공격자 타깃, 후보 ID 획득, 빈 슬롯 편성·해제, PC와 가로 모바일 저장 재진입, 조개 투척 착지·회수, 집게 공격 및 거점 작업·수령을 확인한다. 모바일 패널과 주요 버튼은 가로 844×390 화면에서 맞는지 확인한다. RTC E2E는 두 Edge 컨텍스트로 공개 Nostr 시그널링과 네이티브 데이터 채널을 사용해 후보 반격 타깃, 개체 ID·슬롯 동기화, 소유권 거부, 양방향 RTC 데이터와 같은 참가자 ID 재접속을 확인한다. SDK나 방 전송을 모의하지 않는다. 출력은 무시되는 `artifacts/companions/`에 쓴다.

실물 휴대폰, 서로 다른 NAT 환경, 4인 전체 조합, 장시간 노동·자원 균형 및 모든 카메라/동작 조합은 별도 검증 범위다.

## 공형 발사의 기본 물리

0.28.3은 실제 Rapier 발사체였지만 공형 공격만 중력 배율이 0이었다. 0.28.4부터 발사 초기 속도는 `고정된 공격 방향 × 18m/s + 월드 위쪽 8m/s`, 중력 배율은 1이다. 따라서 기존 월드의 Y축 아래로 20m/s²를 적용받는 실제 포물선 비행이다. 별도 궤적 계산기나 렌더 곡선을 사용하지 않는다. 카메라를 위·아래로 조준하면 수평/수직 초기 속도도 그 방향에 따라 달라진다.

기존 CCD 구체의 반지름을 비행 스프라이트의 실제 윤곽 크기와 맞춘 약 0.29m로 사용한다. 적·지형의 부피 충돌은 기존 Rapier 충돌 이벤트로 처리한다. 첫 적 접촉은 공통 피해를 한 번만 적용한다. `spent` 발사체는 실제 탄도를 따라 계속 낙하하며, 비접촉 시 기존 `12m / 18m/s`의 약 0.667초 발사 수명부터도 낙하가 계속된다. 지형 지원면에서 2틱 연속 확인되면 접촉점에 멈춰 약 0.3초 머문 뒤 회수한다. 스프라이트와 지면 그림자는 동일한 보간된 물리 위치 및 실제 지형 높이를 사용한다.

**복귀는 공격과 분리된 비전투 회수다.** 첫 적 접촉에서 공격 콜라이더는 피해 1회를 확정하고 `spent`가 된다. 지형 접촉이나 사거리 종료로 빗나가도 실제 탄도와 낙하를 계속하며, 지형에 착지하면 접촉점에서 속도·중력을 멈춰 약 0.3초 머문다. 이후 발사체 물리체를 제거하고 동료를 원래 선택자의 앵커로 회수한다. 착지 전 배치 변경은 이 순서를 건너뛰지 않고, 복귀는 추가 피해를 주지 않는다. 사망·연결 중단에는 기존 보관 회수 정책을 유지한다. 노동 동료의 이동에는 이 공격용 중력을 적용하지 않는다.

기존 저장의 물리 스냅샷은 그대로 복원한다. 새 발사 파라미터가 없는 이전 저장의 준비 중 공격도 현재 동료 발사 설정을 사용한다. 이미 비행 중이던 이전 저장의 구체는 저장된 물리 상태로 짧은 남은 수명을 마친 뒤 회수되며, 다음 발사부터 새 기본 물리를 사용한다.
